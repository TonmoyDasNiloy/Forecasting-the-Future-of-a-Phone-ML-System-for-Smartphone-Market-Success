Section 01

System Overview

The Smartphone BI Agent is a cold-start business intelligence platform. Given only the specifications of a phone that has not launched yet, it predicts market outcomes across 8 analytical dimensions — without needing any real sales data for that phone.

What the Agent Does

Traditional BI tools require historical sales data. The BI Agent solves the cold-start problem: it finds the most spec-similar phones in a dataset of 116,481 real-world snapshots, learns from their market outcomes, and projects those outcomes onto your new phone.

The Four ML Pillars

Pillar Model Output
P1 — Market Research XGBoost Classifier + KNN Similarity Market segment, confidence %, closest competitor phones
P2 — Demand Forecast XGBoost Regressor (log1p target) 6-month demand curve, monthly units, total projected sales
P3 — Customer Segmentation KNN Retrieval (StandardScaler) Age, income, gender, RFM segments of predicted buyers
P4 — PMF & Failure Random Forest Classifier PMF score (0–100), failure risk %, go/no-go verdict

What It Does NOT Do

  • Does not use real sales data from your phone (it hasn't launched)
  • Does not connect to live pricing APIs or retailer databases
  • Demand figures are relative projections from comparable phones, not absolute market forecasts
  • News articles are fetched live and may vary in relevance

💡 Best Used For

Pre-launch go/no-go decisions, pricing strategy alignment, identifying your target buyer segment, and stress-testing specs before committing to manufacturing runs.

Section 03

Running Your First Analysis

From opening the app to reading your first results — complete walkthrough.

1
Open the application

Navigate to http://localhost:3000 in your browser. The specs panel opens automatically on the left. The backend must be running on http://localhost:8000.

2
Enter the phone specifications

Fill in all fields in the specs panel — brand, model name, price, hardware specs, and market details. See Section 4 for a full field reference. All numeric fields have sliders for quick adjustment.

3
Click Analyze

Press the Analyze button at the bottom of the specs panel. The loading screen shows live status messages as each ML pillar runs (Market Research → Demand → Customers → PMF).

4
Wait for the dashboard to appear (~3–10 seconds)

The core analysis (4 ML models) runs first and the dashboard appears. Competitor radar and news load in parallel in the background — a spinning indicator in the header shows background loading progress.

5
Scroll through the 8 analytical sections

Sections appear in sequence from Demand Forecast down to Market Intelligence. All data is already loaded — scrolling is instant.

6
Iterate — change specs and re-analyze

The specs panel stays visible. Change any field (e.g., raise the price by $50, increase RAM) and click Analyze again. The dashboard refreshes with the new projection. Use this to find the optimal configuration.

⏱ Loading Time

The first analysis after a cold start may take 8–15 seconds as the ML models load from disk. Subsequent analyses within the same session run faster (2–6 seconds) because models stay in memory.

Section 04

Phone Specification Fields

Complete reference for every input field in the specs panel, including valid ranges and what each field affects.

Identity Fields

Brand
text — e.g. Samsung, Apple, Xiaomi

Affects demand forecasting via brand-level priors. Unknown brands fall back to the geometric mean of all brands in the training set.

Model Name
text — e.g. Galaxy S25 Ultra

Used for display and PDF report labelling only. Does not affect ML predictions.

Region
dropdown — Asia-Pacific, Europe, North America, South America, Middle East, Africa

The KNN competitor search filters by region first. Affects which comparable phones are used for demographics and demand.

Price (USD)
number — $50 to $2,500

The single most influential input. Weighted 2.5× in the similarity search. Drives affordability fit, segment classification, and price vs. category calculations.

Hardware Specifications

RAM (GB)
slider — 2 to 24 GB

Combined with storage in a derived feature (ram_x_mem). Higher RAM pushes the phone toward premium/flagship segments.

Storage (GB)
slider — 16 to 1024 GB

Part of the value score calculation. Also contributes to segment classification alongside price.

Rear Cameras
slider — 1 to 5

Aggregated into cam_total (rear + front). Camera count is a key mid-range vs premium differentiator in the training data.

Front Camera (MP)
slider — 2 to 64 MP

Included in total camera score. High front camera MP correlates with mid-range social-media-oriented buyers.

Battery (mAh)
slider — 1,500 to 7,000 mAh

Combined with screen size into battery_per_inch. Larger batteries shift buyer demographics toward older age groups and value-seekers.

Screen Size (inches)
slider — 4.0 to 7.5 in

Used in battery_per_inch and pixels derived features. Larger screens correlate with mid-range demand and male-leaning demographics.

Screen Resolution (px)
number — e.g. 1080, 1440

The width in pixels. Combined with screen size into a pixels density feature used in segment classification.

Processor Speed (GHz)
slider — 0.8 to 4.0 GHz

Part of the perf_score derived feature (speed × cores). Drives premium vs mid-range boundary in the classifier.

CPU Cores
slider — 2 to 12

Multiplied by processor speed for the performance score. Octa-core (8) is common in mid-range; 10–12 cores push toward flagship.

5G Support
toggle — Yes / No

Strongly influences segment. 5G is now standard in premium/flagship but still a differentiator in budget/mid-range in many regions. Affects price-vs-category calculation.

💡 Tip — Use Sliders for Iteration

All hardware fields have sliders. Click a value, then use the left/right arrow keys to increment by 1 unit. This lets you quickly test how a single spec change (e.g., +2GB RAM) shifts your demand or segment classification.

Section 05

Demand Forecast

Predicts the monthly unit sales trajectory for your phone over the first 6 months post-launch, using XGBoost regression trained on historical launch curves.

What You See

  • Demand curve chart — a line/bar chart showing units per month from M1 to M6
  • Monthly tiles (M1–M6) — individual inset cards showing the exact projected unit count per month
  • Total 6-Month Demand — sum of all monthly projections, shown as a large sky-blue number
  • CLV / Buyer — Customer Lifetime Value in USD, shown as a large emerald number

How the Model Works

The demand model (XGBoost regressor, 700 estimators, max depth 8) predicts log1p(units_sold_monthly). The output is inverse-transformed with expm1() to get real unit projections.

A brand demand prior is computed on the training fold for each brand and injected as a feature. Unknown brands fall back to the geometric mean across all brands, preventing zero-demand predictions for new entrants.

CLV Formula

Customer Lifetime Value is calculated as:

CLV = (price × gross_margin) × repeat_factor × 2.4 years
repeat_factor = repeat_rate / (1 − repeat_rate × (1 − return_rate))

The 2.4 is the loyalty horizon constant — the average number of years a buyer stays engaged with the same brand, derived from the training dataset.

How to Interpret

SignalMeaningAction
Demand peaks at M1 then falls sharply Hype-driven launch with weak retention Invest in post-launch engagement; consider a storage upgrade SKU
Demand rises from M1 to M3 then flattens Word-of-mouth-driven growth, stable market Healthy sign — focus on review seeding for M1–M2
Low CLV despite decent demand Low repeat rate — buyers don't return to the brand Review pricing and after-sales support strategy
High CLV, moderate demand Premium niche — fewer but more loyal buyers Lean into subscription services, accessories, warranties
Section 06

Customer Profile

Reveals who will buy your phone — age groups, income levels, and gender split — derived by finding the most spec-similar phones in the dataset and reading their real buyer demographics.

What You See

  • Buyer Persona card — a plain-English summary: "A 25–34 year-old, mid-income shopper who is typically a loyal repeat buyer. Leans Male (52%)."
  • Age donut chart — percentage split across 18–24, 25–34, 35–44, 45–54, and 55+ age bands
  • Income donut chart — Low / Lower-mid / Mid / Upper-mid / High income tier breakdown
  • Gender donut chart — Male / Female / Non-binary split

How It's Derived

The KNN retrieval engine (Pillar 3) searches for the k most spec-similar phones in the dataset using 12 normalized features. Price is weighted 2.5× more than other specs. The buyer demographics of those similar phones are aggregated and returned as your predicted buyer profile.

Key Dimension Meanings

DimensionWhy It Matters
Age Groups Drives which ad channels, messaging, and distribution work. 18–24 → TikTok/social; 35–44 → LinkedIn/professional; 55+ → TV/print.
Income Level Confirms whether your price point reaches your actual buyers. A phone with 60% Low/Lower-mid buyers priced at $900 will struggle.
Gender Split Informs product design, color choices, and influencer partnerships. Not a rigid rule — treat as a probabilistic tendency from comparable phones.

⚠ Important Caveat

Demographics are inferred from spec-similar phones, not from a direct survey of your phone's buyers. Treat these as probabilistic estimates for planning, not guaranteed audience breakdowns. Large, distinctive spec combinations (e.g., ultra-premium 12GB RAM + 5G + $200 price) may have fewer similar comparables, making predictions less precise.

Section 09

Competitor Gap Analysis

A radar chart comparing your phone's specs against the average of its nearest competitor phones across key dimensions.

What You See

  • Price vs Category Avg — how much above or below the average price of phones in your predicted segment
  • Market Segment + Confidence bar — the XGBoost classifier's predicted tier and certainty
  • Competitor Radar Chart — polygon overlay comparing your specs vs competitor average across 5–8 dimensions

Reading the Radar

Each axis of the radar represents a normalised spec dimension. Your phone's polygon is shown in one colour; the competitor average in another. Areas where your polygon extends further than the competitor's are your spec advantages. Areas where it falls inside are gaps.

Price Signal Interpretation

Price vs CategorySignalRecommended Action
> +15%Premium-priced vs peersEnsure radar shows clear spec advantages to justify the premium
−5% to +15%In-line with marketCompete on brand, software, or marketing differentiation
< −5%Value leaderStrong positioning — communicate the value story proactively

⏳ Loading Behaviour

The competitor radar loads asynchronously after the core analysis. It may take 5–15 seconds to appear. A spinning loader is shown in its place while it loads. This does not block the rest of the dashboard from displaying.

Section 10

Optimal Price Recommender

Runs a 14-point sweep across a price range and finds the price point that maximises projected revenue, adjusted for spec quality relative to competitors.

What You See

  • Your Price — the price you entered in the specs panel
  • Recommended Price — the price point at maximum revenue on the demand curve
  • vs Category Avg — price gap vs the average for phones in your segment
  • Revenue / Demand Curve Chart — full 14-point sweep showing revenue and demand at each tested price
  • Assumptions strip — Gross Margin (40%), Demand Elasticity β (1.30), Spec Ratio cap (0.8–1.25×)

How the Sweep Works

The algorithm runs across 14 price points around your entered price. At each point it estimates:

  1. Spec ratio — your spec score vs competitor average, clamped to 0.8–1.25× to prevent outlier distortion
  2. Adjusted demand — base demand scaled by spec_ratio / price_ratio^β where β = 1.30 (price elasticity)
  3. Revenue — adjusted demand × price × gross margin (40%)

The price with the highest resulting revenue is marked as the recommendation.

Key Assumptions to Note

AssumptionValueWhat to Do If It Doesn't Apply
Gross Margin 40% If your actual margin is different, scale the recommended revenue accordingly — the optimal price point doesn't change
Demand Elasticity β 1.30 Higher β (price-sensitive market) will shift the recommendation lower; lower β will push it higher
Spec Ratio Cap 0.8–1.25× Prevents extreme outlier specs from distorting the model — representative of real-world positioning constraints

💡 Using the Price Optimizer Iteratively

If the recommended price is higher than yours, try entering that price in the specs panel and re-running the analysis. Check if the segment classification changes and whether the affordability feed still supports that price for your buyer base.

Section 11

Product-Market Fit

The final go/no-go verdict. Combines a composite PMF score with a Random Forest failure risk classifier to produce a clear launch recommendation.

What You See

  • Verdict banner — GO FOR LAUNCH (green), CAUTION (amber), or RECONSIDER (red)
  • PMF Gauge — a semicircular gauge from 0 to 100 with colour zones
  • PMF Score — the composite product-market fit score out of 100
  • Failure Risk % — the Random Forest's estimated probability of product failure
  • 6 KPI tiles — PMF, Risk, Demand, CLV, Confidence, Segment in compact inset cards

PMF Score Formula

PMF = 0.25 × NPS_score
    + 0.20 × repeat_purchase_rate
    + 0.20 × recommend_rate
    + 0.15 × (1 − return_rate)
    + 0.10 × (1 − warranty_claim_rate)
    + 0.10 × demand_growth_slope

All components are min-max normalised to [0, 1] before weighting.
Final PMF score = (1 − failure_probability) × 100

Go / No-Go Thresholds

Failure RiskVerdictGuidance
< 15% ✅ GO FOR LAUNCH Strong product-market fit. Proceed with planned launch and standard marketing investment.
15–35% ⚠️ CAUTION Moderate fit. Address the weakest spec dimensions (check radar) before launch. Consider a soft launch first.
> 35% 🚫 RECONSIDER Poor fit. Major misalignment detected — revisit pricing, specs, or target region before committing.

What the Random Forest Detects

The failure classifier (500 estimators, max depth 12, class_weight="balanced") is trained on phones that historically fell in the bottom 25% of their PMF score distribution. Features include all 7 engineered specs plus brand and region. The model is particularly sensitive to price-to-spec mismatches — phones priced too high for their spec tier in a given region.

Section 12

Market Intelligence

Live news articles about your phone, its competitors, and the broader smartphone market — fetched in parallel while the ML analysis runs.

What You See

  • Grouped articles: Your Phone (up to 9 articles) and Competitor (up to 11 articles)
  • Each article shows: headline, source, date, and a brief excerpt
  • Articles are clickable links that open in a new tab

How News Is Fetched

After the ML analysis completes, the backend fires up to 8 parallel web requests (ThreadPoolExecutor, max 8 workers) to search for articles. Each request has a 15-second timeout. Articles are filtered and grouped by topic (your phone vs competitors) before being returned to the dashboard.

What to Look For

  • Competitor announcements — is a direct rival launching something at a similar price point in the same quarter?
  • Market trend signals — are 5G or foldable stories dominating? Does your phone fit the current narrative?
  • Regional coverage — is your target region well-represented in the news? Sparse coverage may indicate lower analyst/media attention.

⚠ News Loading

News loads asynchronously. The spinning "Fetching news…" indicator in the top bar disappears when loading is complete. If you re-run analysis before news finishes loading, the previous news results are cleared and fresh requests are fired.

Section 13

Live Comparison Mode

The specs panel is docked alongside the dashboard — making the BI Agent the only pre-launch tool that lets you watch every metric respond in real time as you change specs.

How to Use It

1
Run a baseline analysis

Enter your initial phone specs and click Analyze. Let the full dashboard load including competitor radar and news.

2
Keep the specs panel open

The panel is docked by default. Do not close it. Scroll through the dashboard to understand the baseline metrics.

3
Change one variable

Adjust a single field — for example, increase price from $320 to $370. Leave everything else the same.

4
Click Analyze again

The dashboard refreshes. The specs panel stays open. You can immediately see how demand changed, whether the segment shifted, and how affordability was affected.

5
Iterate methodically

Change one variable at a time so you can attribute changes in output to specific inputs. Common experiments: ±$50 price, ±2GB RAM, region change, 5G on/off.

Most Impactful Experiments

ChangeSections Most Affected
±$50 priceAffordability Feed, Segment (may flip tier), Price Optimizer, PMF
+2 GB RAMCompetitor Radar, Segment confidence, PMF score
Toggle 5G on/offSegment classification, Price vs Category, Demand Forecast
Region changeAll sections — KNN search re-filters by region, demographics shift
Budget vs flagship brandDemand Forecast (brand prior), PMF, Customer Profile

✅ Best Practice — The Price Ladder

Run the same specs at $50 increments across 4 price points. Record the PMF score, affordability %, and total demand for each. You will quickly identify the "sweet spot" where you maximise revenue without triggering a segment downgrade or an affordability mismatch.

Section 14

Downloading Reports

Export a formatted PDF summary of the current analysis results for sharing with stakeholders.

How to Download

Click the ⬇ download button at the bottom of the sidebar. This button is disabled (greyed out) until at least one analysis has been run. Clicking it opens a new browser tab with a formatted HTML report and immediately triggers the browser's print dialog — select "Save as PDF" from your printer list.

What the Report Contains

  • Phone model, price, and region
  • Go/No-Go verdict with PMF score and failure risk
  • 6-Month demand forecast (monthly breakdown table)
  • CLV per buyer
  • Key metrics grid (segment, confidence, price delta)
  • Age and income customer profile breakdown
  • Model attribution footnote (XGBoost + Random Forest + KNN)

📋 Report Note

The PDF report is a snapshot of the most recent analysis. If you re-run analysis with different specs, the report will reflect the new results. The competitor radar chart and news articles are not included in the report (they are live/async components).

Section 15

Interpreting Signals

Quick-reference guide for the most common output patterns and what they mean for your launch strategy.

Common Patterns

Pattern Likely Cause Recommended Response
GO verdict + High demand + Low CLV Volume product in competitive segment; buyers don't repeat Focus on volume distribution channels; minimise after-sales cost
CAUTION + "Priced above audience" Price exceeds what buyers in your predicted segment can afford Reduce price by 10–15% or target a wealthier region
High PMF + Low demand Great fit for a small niche — possibly too premium or too regional Consider expanding to additional regions; invest in niche community marketing
Segment: Budget + 5G enabled Budget phone with 5G is unusual — model will classify with lower confidence Strong market opportunity if confidence is ≥70%; otherwise check pricing
Rec. price > entered price Your specs could command a higher price for max revenue Test the recommended price in a new analysis; check if affordability still supports it
RECONSIDER + 55+ buyer age dominant Phone appeals to older buyers but has premium specs they may not value Reduce spec complexity; emphasise battery life and camera simplicity
High "At-risk" buyer base (>50%) Similar phones have historically failed to retain buyers Plan aggressive after-sales: software updates, loyalty discounts, community

Confidence as a Reliability Signal

The classifier confidence % tells you how certain the XGBoost model is about the segment it assigned. Use it to calibrate how much to trust the other outputs:

≥ 80%
High confidence — trust fully
60–79%
Moderate — cross-check competitors
< 60%
Low — phone is atypical; use caution
Section 16

Troubleshooting

Solutions to the most common issues encountered while running the BI Agent.

Problem Cause Fix
Dashboard stays on loading screen Backend is not running or has crashed Start the backend: uvicorn backend.main:app --port 8000 from the project root. Check localhost:8000/api/health.
"Analysis failed" error banner Network error or invalid input rejected by Pydantic Ensure all fields are filled. Price must be a positive number. Check browser console for the exact error message.
Competitor radar never appears Competitors endpoint timed out or phone has no KNN matches Wait 30 seconds — the background request retries. Very unusual spec combinations (e.g., $50 phone with 16GB RAM) may return no competitors.
News panel shows no articles News API timeout or rate limit Re-run analysis. The news endpoint uses up to 8 parallel requests with 15s timeout. Intermittent failures are normal.
Specs panel disappeared Toggled closed via the ◀ HIDE button or ✕ in the panel Click the ▶ SPECS button in the sidebar (bottom section, same icon). The panel slides back in.
Dark mode cards not visible Browser cached an older CSS version Hard refresh: Ctrl + Shift + R (Windows) or Cmd + Shift + R (Mac).
First analysis takes >30 seconds Models loading from disk on cold start This is normal for the first run. Subsequent analyses in the same session are significantly faster.
Download button is greyed out No analysis has been run yet in this session Run at least one analysis. The button activates as soon as results are displayed.

System Requirements

  • Backend: Python 3.10+, FastAPI, Uvicorn. Run pip install -r requirements.txt first.
  • Frontend: Node.js 18+, Next.js 14+. Run npm install then npm run dev.
  • Browser: Chrome 110+ or Firefox 115+ recommended. Safari is supported but some CSS animations may differ.
  • Ports: Backend on 8000, Frontend on 3000. No other services required.
  • Memory: At least 4GB RAM available for the ML models (XGBoost + Random Forest + KNN fit in ~1.2GB).
