3. XGBoost — Gradient-Boosted Trees (Pillars 1A & 2)

3.1 Architecture

XGBoost builds an additive ensemble of CART regression trees. Each new tree is fit to the gradient of the loss left by the current ensemble (functional gradient descent):

F_0(x) = base score F_t(x) = F_(t-1)(x) + η · f_t(x) η = learning_rate f_t = argmin_f Σ_i [ g_i f(x_i) + ½ h_i f(x_i)² ] + Ω(f) Ω(f) = γ·T + ½ λ ‖w‖² (T leaves, leaf weights w)

g_i, h_i are the first/second-order gradients of the loss. Classification uses softmax (multi:softprob); regression uses squared error on the log-target.

┌────────┐ ┌────────┐ ┌────────┐ input ─► │ tree 1 │ + │ tree 2 │ + ... + │ tree N │ ─► Σ ─► softmax / value └────────┘ └────────┘ └────────┘ each tree corrects the residual error of the previous sum

4. k-Nearest Neighbours — Retrieval (Pillars 1B & 3)

4.1 Architecture

k-NN is non-parametric / instance-based: there is no trained weight matrix. The "model" is the standardised catalogue itself plus a distance function.

1. price' = ln(1 + price) (log-scale skewed feature) 2. z_i = (x_i − μ_i) / σ_i (standardise each feature) 3. z_price ×= 2.5 (up-weight price — defines phone "type") 4. d(a,b) = √ Σ_i (z_a,i − z_b,i)² (weighted Euclidean) 5. retrieve k nearest within the same region
query phone ─► standardise+weight ─► distance to every catalogue phone │ region filter ──┤ ▼ k nearest neighbours │ Pillar 1B: return them as competitors │ Pillar 3: average their real ▼ buyer demographics

Distance features: price_usd, num_cores, processor_speed, battery_capacity, ram_capacity, internal_memory, screen_size, refresh_rate, primary_camera_rear, 5g_or_not, resolution_height, resolution_width

Why k-NN for demographics. A direct specs→demographics regressor scores R²≈0. Retrieval works because "who buys this kind of phone" is best answered by the real buyers of similar phones, not by a parametric function of the specs.

5. Random Forest — Bagged Trees (Pillar 4)

5.1 Architecture

A Random Forest trains many decision trees independently on bootstrap samples with a random feature subset at each split, then averages their class probabilities (bagging). This decorrelates the trees and reduces variance.

P(failure | x) = (1/N) Σ_t P_t(failure | x) N = number of trees each tree t: bootstrap rows + random √p features per split class_weight = "balanced" → re-weights the 25% failure class
bootstrap 1 ─► tree 1 ─┐ training bootstrap 2 ─► tree 2 ─┤ data bootstrap 3 ─► tree 3 ─┼─► average probabilities ─► P(failure) ... │ bootstrap N ─► tree N ─┘

Why a forest, not boosting, for PMF. The constructed failure label is noisier and the dataset smaller (one row per phone), so bagging's variance reduction and the class_weight="balanced" option are a better fit than boosting, which could over-fit the quartile cut-off.

6. Training Architecture

GroupShuffleSplit(test_size=0.2, random_state=42) group key = brand_name + "__" + model → a phone is wholly in train OR test leak-free priors (P2 brand prior) fit on the TRAIN fold only, mapped to both folds cold-start rule: P2 & P4 never receive post-launch columns as features

This split is the central guard against inflated metrics: random row-splitting would place the same phone in both folds and let the trees memorise it.
